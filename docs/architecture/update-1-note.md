1. **Capture never touches the live agent.** The tee forwards each frame first and then offers a copy to a per-capture collector through a bounded, non-blocking send. A copy that can't be taken is dropped and counted, and the gap is marked by the dropped range, sequence holes or a missing close. I removed the frame-holding rule, backpressure onto calls, and "a recorder that is behind slows the call". The collector restarts on its own and taps reconnect, so recording recovers without touching the agent. I also moved the plugin capture sidecar onto its own connection, because sharing the agent's connection touched the live path. Shims exit as soon as their command does. The risk about a wedged disk slowing the agent is gone. In its place is a risk about the relay hop that any in-path route adds.
2. **Capture routes.** In-path routes (taps) and after-the-fact routes (transcript readers, `phoenix record`) are chosen per surface, and every event carries its route. I added a `transcripts` unit (section 3.3) and a "Fill gaps" setup step. That step uses mechanical derivations first, then the setup agent. A fill is tagged derived only when its values appear verbatim in cited evidence, and synthesized otherwise. Synthesized fills taint and discount just like simulator answers.
3. **Start anywhere.** The bundle keeps the run's evidence whole. The frozen prefix is cut per Replay at any start point from the beginning to the mark, the clock is re-anchored there, and `scope: continuation` means after the start point. The start point is part of the plan and the baseline key.
4. **Server harnesses.** One launch is one Run by default. Recipes can declare task keys (session or thread id), and harnesses can call `phoenix task start/end`. Runs are computed by the reader, and events it can't place stay unattributed. The harness contract's `run` gains a `serve`/`submit` form, and the runner replays one task in a fresh server.
5. **Containers only.** I removed the VM driver and QEMU. The clock is libfaketime driven by a clock file the engine rewrites, plus a probe and an ELF check that refuse Replays the clock can't cover.
6. **Working directory.** A snapshotter runs beside the harness and never ahead of it. In git it records HEAD and copies only what differs, and it marks files that changed during the copy as uncertain. The snapshot goes into the manifest and the sample's file tree.
7. **Privacy.** Capture strips secrets only and keeps everything else raw. Personal data is scrubbed, and media and unscanned bodies withheld, only in a packed revision that the person re-approves.
8. **Discounted passes.** They count toward neither the set rule nor a patch until confirmed by an emulator replay, a fresh recording (`phoenix moment confirm`), or `phoenix pass accept`. I added an `approvals` unit so the Workbench can't reach any ledger write.
9. **Samples.** The check holds `samples: { base: 2, tiebreak: 1 }`, settable per moment. The runner adds the tiebreak only on disagreement, and the comparison with baseline uses pass share, since sample counts can differ.
10. **Capture-time reads.** They stay opt-in per connector, now on their own connection.
11. **Corrections.** They are entered only through `phoenix correct`. Reading them from harness prompts isn't in the design.
12. **Auto-lock.** It stays per moment (`lock: auto` in the manifest).
13. **Login modes.** Recipes declare routes per harness version and login mode. Pinned endpoints use the forward proxy or the transcript route. The spec's fx and pi question stays as a risk.
14. **No latency limit.** No performance goal appears, and the overhead question is removed.
15. **Drift.** A harness that drifts on an echo Replay is limited to the beginning, with no extra contract item.

All 13 earlier questions are answered and removed. There are four new questions:
- **Clock for static and Go binaries.** libfaketime can't reach them. Codex's default Linux release target is a static musl build. Should such a Replay be refused, or run on the real clock and graded down?
- **Docker Desktop and Podman on macOS.** Both run their own Linux VM. Does that fit "no hypervisor"?
- **Ignored files.** Should ignored files in the working directory be copied rather than listed?
- **Unscanned bodies.** Bodies the secret scanner can't read are kept raw locally. Should they be withheld at capture instead?
