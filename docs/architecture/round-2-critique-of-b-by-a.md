The other design has useful boundaries: protocol relays, independent recording segments, immutable candidates, isolated checks, and a small Workbench API. Its main defects are lost evidence, unsupported claims of exact restoration, and verdict rules that can certify a change without satisfying the locked check.

1. **Capture deliberately loses the evidence Phoenix exists to preserve.** Sections 3.2 and 5 drop events when the queue fills or storage fails. That conflicts with SPEC §3 Capture, “every tool call, every response,” and the requested fail-safe property. A second model-API recording cannot recover calls never shown to the model, CLI filesystem effects, missing stream segments, or a simultaneous recorder failure. A gap marker cannot always survive the failure that prevented the event from being written. The criticism of synchronous recording is nevertheless valid: durability adds latency and can affect production availability. Neither design can simultaneously guarantee durable recording, uninterrupted forwarding, and unchanged timing under storage failure. This needs an explicit product decision, not a claim that dropping events preserves the whole spec.

2. **The append-only store’s crash guarantees exceed its mechanism.** One `write()` can write fewer bytes than requested; success does not establish power-loss durability. Periodic synchronization explicitly leaves a loss window. Publishing a synchronized blob with `rename()` also requires durable directory publication before a durable reference can safely acknowledge it. See [`write(2)`](https://man7.org/linux/man-pages/man2/write.2.html) and [`fsync(2)`](https://man7.org/linux/man-pages/man2/fsync.2.html). Per-recorder plain files are a good simplification, but they still need complete-write handling, commit boundaries, synchronization, and recovery rules. Those requirements are not peculiar to SQLite.

3. **Replaying responses through edited code is not exact mark restoration.** Section 3.6 ignores system prompts and tool descriptions when matching the frozen prefix. Edited code can change local variables, cached tool definitions, message construction, filesystem effects, and background work even when it requests the same tool calls. Recorded responses do not undo those differences. A changed prompt used to initialize an internal cache is a simple counterexample. SPEC §3 Moments requires the prefix to remain frozen exactly; arbitrary continuation cannot be obtained from the three-field harness declaration alone. Recipes must use an actual continuation boundary or report that the mode is unavailable. This is a real limitation of the spec’s universal claim, not a reason to mislabel reconstruction.

4. **Its mark definition imports future observations into the past.** Section 3.4 places an entire call before the mark when the call started before it, even if its response arrived afterward. A model could not have consumed that future response at the marked instant. Timestamp sorting across recorders also does not establish causality. The mark needs a causal frontier with pending calls, not a total order that silently completes them. This matters directly to SPEC §3’s “any step” requirement, especially concurrent tools and streaming output.

5. **The matching rules silently manufacture additional observations.** Section 3.5 repeats the last recorded answer after occurrences are exhausted. A changing inbox, a paginated search, and a polling operation cannot safely reuse their final observed answer indefinitely. Removing plugin-declared “volatile” arguments can likewise erase meaningful distinctions. [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html) standardizes JSON representation, not semantic equivalence. An exhausted recording must fall through unless connector semantics establish valid reuse. The simulator cache also needs world-state identity: the same arguments after different writes must not receive one globally cached answer.

6. **The overlay contract is too weak for its advertised statefulness.** An entity map describes paths and CRUD shapes, not recurrence exceptions, permission-dependent results, attendee side effects, pagination, or conditional writes. Sections 3.5 and 3.7 do not specify atomic publication of a selected recording, write effect, emulator state, and response. Restarting an interrupted sample is safe from production writes, but it does not preserve the exact simulated history if already-observed model outputs or simulator choices are replaced. SPEC §3’s overlay and stateful-fake checks require connector-owned semantics and recoverable state transitions, not just entity extraction.

7. **The network proof is incomplete.** Docker explicitly says an internal network can reach its gateway IP and appropriately configured host services; see [`--internal`](https://docs.docker.com/reference/cli/docker/network/create/#internal). A DNS catch-all does not remove that path. An allowlist of model hosts is also weaker than an inference-only broker: the same host can expose file, administration, or other APIs. SPEC §2’s replay safety requires explicit host-network denial, no production IPC or mounts, and a broker restricting operations and provider-side tools—not just destinations.

8. **The grading rules change the spec.** Section 3.8 allows a pass merely because the baseline already met the check, although SPEC §3 says a pass means better than the baseline on the same model and Moment. More seriously, it drops tainted expectations whenever untainted ones remain. A check requiring “move the right event and notify attendees” could pass by assessing only the move. A discounted label does not repair an unproved required condition. Keep deterministic failures binding; otherwise an essential condition resting on invented facts makes the assessment incomplete. Previously passing regression Moments need preservation, not repeated strict improvement.

9. **The approval lock has no independent authority.** Hashes stored beside mutable data detect accidental changes only if an approved digest is retained somewhere the Improver cannot replace. An import rule is useful but cannot stop an agent with direct filesystem access from changing both `check.yaml` and `moment.lock.json`. SPEC §2 requires an actual capability and filesystem boundary. Conversely, forbidding all code in a shared bundle conflicts with custom TypeScript checks in SPEC §3; either the locked check code or a precise independently supplied dependency must be available.

10. **Privacy has an unsafe exception and insufficient provenance.** Section 5 stores malformed data “raw,” contradicting the rule that secrets and personal data are redacted when recorded. Assembling an entire long-lived stream before redaction also leaves no durable partial evidence. A count does not identify which task-relevant facts were removed. Redaction must be stateful across chunks, unsafe material must be withheld rather than persisted raw, and its effects must be attached to the affected evidence. Re-redacting an exported bundle changes its hashes and potentially its check meaning; it requires a new revision rather than an unchanged approval lock.

11. **Several restrictions are unnecessary or incomplete.** Scenarios always start from the beginning in §4, despite SPEC §3 saying both origins replay the same way. Ignoring every untracked file prevents an Improver from adding an allowed source file. Requiring a git worktree excludes otherwise valid self-built harnesses. Deferring clocks and fidelity until after declaring the first complete replay loop ignores requirements already needed by that loop. Promising execution support for every older format major is an unrequested permanent compatibility obligation.

12. **Some counterarguments are sound; others attack mechanisms absent from the supplied design.** Transparent live MCP relaying is preferable to terminating both sides through SDKs. The official SDK documents explicit modern-protocol opt-in and probe behavior, so Phoenix must not introduce its own negotiation during Capture ([SDK guide](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28.html)). Independent plain-file journals also remove an unnecessary native database dependency. But the supplied design does not specify gVisor, TCG instruction counting, or a Workbench dependency on Setup. Those objections do not apply to it. Guest wall time does not require instruction-count emulation; the real issue is sharing the clock with fakes and covering every relevant process. A clock probe cannot prove that coverage, as [libfaketime documents runtime bypasses](https://github.com/wolfcw/libfaketime).
