1. **Durable admission versus silent availability-first loss.** Independent journals simplify recording, but they do not remove the need to persist before acknowledging evidence. I favor stopping affected forwarding over dropping the only record of a failure. If the user prioritizes production availability, that is a legitimate requirement change—not an equally lossless implementation.
2. **A replayed transcript is not arbitrary execution-state restoration.** Ignoring edited prompts while replaying old responses can reproduce a sequence without reproducing the original state. Exact mark replay needs a real continuation boundary; blocking unsupported marks is more honest than advertising a universal mechanism that fails on ordinary hidden state.
3. **Required check conditions cannot be discarded because they are tainted.** A pass must satisfy the locked target, and a target improvement must beat its same-model baseline. Keeping only convenient untainted expectations, or exempting an already-passing baseline from improvement, changes the meaning of pass.
4. **Recording reuse and write handling need semantics.** Repeating the last response forever is not truthful generic replay. Declared no-op writes and causally matching recorded suffixes can continue safely, but unknown state-changing effects cannot justify arbitrary stale reads. Connector-owned state and explicit applicability are the necessary distinction.
5. **Network destinations and colocated hashes are not sufficient boundaries.** Docker internal networking retains documented host reachability, a model host can expose more than inference, and a mutable lock beside mutable data cannot prove approval. Host-enforced isolation, an inference-only broker, and approval authority outside the Improver’s writable space directly implement the spec’s safety rules.
