1. **Capture must never block or pause the harness.** The other design records before it delivers and stops admitting calls when storage fails. Spec section 3 says Capture runs "all the time and in production, without changing what the agent does". A durable commit per event means a WAL sync per commit under `synchronous=FULL` ([SQLite WAL](https://sqlite.org/wal.html)), and on macOS that is still not a real flush without `fullfsync` ([pragma](https://www.sqlite.org/pragma.html#pragma_fullfsync)). My design writes each event straight to the operating system, syncs on a timer, marks every gap, and has the model-API record as a second witness. It loses at most the unsynced tail on a power cut and never costs the person their production run. The user question stays open; the default should be the one the spec's sentence describes.

2. **Plain files are the store; no SQLite.** The spec's "open formats" principle makes the trace a plain file, not an export of a database. Per-recorder append-only files need no shared writer, so one short-lived CLI shim or proxy cannot stall or take down another, and there is no native addon to install under npx. The matcher's index is a map built in memory at Replay start.

3. **The MCP proxy is a byte relay, not an SDK client-server pair.** With two protocol eras live and current clients probing with `server/discover`, sometimes by launching the server a second time ([SDK 2026-07-28 support](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28.html)), a proxy that terminates the protocol has to imitate each upstream's era exactly or it changes what the harness sees. A relay cannot get this wrong, carries revisions that do not exist yet, and leaves era handling to the Replay responder where the recording dictates the answer.

4. **Replay from the mark works for every harness by relaunching with a frozen prefix.** The other design depends on a harness's continuation import or an unexplained switch from original to candidate code, and blocks the mark otherwise. Answering every pre-mark model request and tool call from the recording needs nothing from the harness beyond the three declarations the spec allows, and reports prefix drift when an edit changes the prefix. Hidden state outside the model and tool calls is the stated limit of both approaches.

5. **Containers first, a VM only when the clock probe fails, and no gVisor or instruction counting.** The spec's threat is a write to a real system, which a network with one peer and no credentials closes. gVisor defends against kernel exploits by the person's own harness and has no supported path on Docker Desktop ([issue](https://github.com/docker/desktop-feedback/issues/364)). QEMU's instruction counting is a software-emulation feature ([docs](https://www.qemu.org/docs/master/devel/tcg-icount.html)); setting the clock inside an accelerated guest is enough.

6. **After an untracked write, keep answering and taint; do not diverge.** The spec says simulator "writes are no-ops" and lists Banking as "recorded reads, no-op writes". Diverging on every read after an unknown write makes that tier unusable. Serving the recorded read, flagging the connector, and discounting expectations that depend on it is honest and keeps the tier the spec describes.

7. **The Workbench must not be able to import the code that writes checks.** The other design's unit table lets the Workbench interface depend on `setup`. "Whoever is trying to pass it can never edit it" is stronger as a build-time import rule plus an unmounted bundle than as a runtime permission inside the process the Improver drives.

8. **Four provenance values, as the spec names them.** "Real, recorded, derived or synthesized" is the spec's vocabulary. Emulated answers are derived from recorded state, and seeded data is a property of the moment's source, reported once per connector as its origin. Six per-answer values add a distinction the grade does not use.
