1. **Durable Capture versus unconditional forwarding.** I retain durable admission and fail-closed storage behavior because lost observations cannot be recreated later. Best-effort forwarding is a reasonable availability policy only if the user explicitly relaxes complete Capture; it cannot simultaneously satisfy the stated lossless goal.
2. **Honest restoration versus approximate prefix matching.** I reject ignoring prompts and tool descriptions to force a prefix match. The strongest reason is causal: changed code can alter state before any matched model response. Supported continuation or original-prefix reconstruction is necessary to claim the same Moment.
3. **One state authority versus generic entity overlays beside emulators.** I retain connector-owned semantics and transactional state publication. Calendar recurrence alone shows why paths to IDs and items cannot determine write effects, and two independent mutable worlds cannot provide trustworthy end-state checks.
4. **Complete evidence versus discounted passes.** I require every necessary condition to be assessable and keep improvement distinct from an already-passing baseline. Otherwise synthesis or divergence can remove the difficult part of a locked correction while leaving an attractive pass label.
5. **Enforced isolation and covered time versus declarative labels.** I retain externally enforced host/network restrictions, OS-isolated checks, and a guest-wide clock option. Docker internal networking, Node permissions, and a `clock: host` label each leave a documented gap in the spec’s guarantee.
6. **Transactional local storage versus unsynchronized segment files.** The portable format should remain plain files, but an indexed transactional journal simplifies atomic mutation, response, and recovery records. A synchronized file implementation could also work; the proposed timestamp merge and torn-line handling do not supply those semantics.
