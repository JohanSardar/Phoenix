# Trace event

A trace is JSON Lines, one event per line, in segment, import and notes files (ARCHITECTURE.md sections 3.4 and 6). Every event carries `v`, `capture`, `stream`, `seq`, `ts` and `kind`. `route` says which capture route produced it: `tap`, `transcript` or `import`. Agent-level traffic has `layer: agent`; traffic a local MCP server made underneath has `layer: under`, with `parent` and `parent_basis: sole-in-flight` when the link is inferred. `id` is the event's id, which marks, start points and `parent` refer to.

The body is stored as received, apart from stripped secrets: inline, or as a blob digest above the size threshold, with `content_encoding` noted when a secret forced it to be stored decoded. `chunks` give arrival times for streamed bodies, `partial` marks a message that lost frames, and `dropped` carries the sequence range and bytes of copies lost before this one. `verbatim` lists the fields an imported event took from its log as written. Replay results carry `provenance` and `resolver`. `secrets` lists each stripped value's location and rule, or is `unscanned`.
