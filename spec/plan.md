# Replay plan

`plan.json` is the resolved plan the runner writes before a Replay (ARCHITECTURE.md section 3.11). Everything after it is a function of the plan, and its hash is the Replay's identity and the baseline cache key. It holds the bundle digest and check hash, the base and candidate tree digests and the harness image digest, the model and parameters (an alias marked as one), the start point (`beginning`, `mark`, `echo` or `{ at: <event id> }`) and the sample rule, the resolved plugin versions, the simulator model and configuration when one is used, the container runtime and clock probe command, the recipe's declared login context when the request supplies one (`login_context`), the version of the engine's matching rules, and `network` when the replay lets the box reach the internet. `network` is absent when the level is off, so the box reaches only the LLM. With `level: packages` it lists in `allow` the package registry hosts from the runner's network config (`packages/runner/network.json`); with `level: open` it lists in `deny` the hosts the plan's plugins name in `recognize.hosts`, which keep their copies. The request names the level as `network: off | packages | open`, and `phoenix replay start --network <level>` overrides it. Matching rules version `2` files system-role turns and per-turn cache directives of the messages dialect under configuration and matches a non-JSON prefix request by its bytes.
