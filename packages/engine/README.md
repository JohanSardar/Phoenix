# Engine

`startEngine` is the replay-side server for one sample. It builds the answer index from the run's evidence, writes the sample trace as a capture directory in the live format, and hosts the taps with responders as their backends: `accept` takes a relay connection (`{ destination, stream }`, as `EngineChannel` yields them) and serves it as MCP stdio when its destination host is bound in `routes.mcp`, otherwise as HTTP through `gateway`, routed per request by host through `routes.http`.

Until every exchange of the frozen prefix has been served, model requests get the recorded response after `comparePrefixRequest` and tool calls get their recorded results; the first difference stops the sample with a `prefix-drift` divergence. From then on model requests go through the model route (inference operations only, the real credential from `model.provider.headers` added here, no redirects followed, the `Date` header in virtual time) and tool calls go through the answer chain. Every event, including each answer, is synced to the sample trace before the answer is sent. `stopped` resolves with the first divergence (also written to the trace) or with an interruption such as a provider transport failure, and every open connection is then closed. A `start-point` meta event marks where the continuation begins and lists `prefix_edits`.

`VirtualClock` starts at the run's captured start time and is re-anchored to the captured time at the start point when the prefix ends. `onAnchor` lets the runner rewrite the sandbox clock file. The engine has no CLI or MCP Streamable HTTP responder yet; such a connection is a divergence.
